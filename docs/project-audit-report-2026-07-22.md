## 2. 当前项目结构

### 前端

- Vue 3 + TypeScript + Vite 8。
- Pinia 已安装；当前主要页面状态仍集中在组件内。
- Axios 访问 REST API。
- Tiptap 3 + Markdown + KaTeX 提供学习笔记编辑能力。
- 当前公开模块：主页、文章、美食、学习笔记、关于。
- 当前后台模块：文章管理、菜品管理、学习笔记工作台。

### 后端

- Java 21 + Spring Boot 3.5.16。
- Spring MVC、Bean Validation、Spring Data JPA。
- Spring Security + HS256 JWT + BCrypt 管理员密码。
- Flyway 管理 PostgreSQL 结构，目前迁移版本为 V8。
- 现有 5 个 JPA Repository，分别服务文章、菜品、学习笔记、笔记附件和管理员数据。

### 数据库

- PostgreSQL 是文章、菜品、学习笔记、附件和管理员账号的权威数据源。
- 自动化测试使用独立真实数据库 `yubai_blog_it`，每轮重建 `public` schema，不污染开发库。
- 浏览器联调使用开发 PostgreSQL 数据库。
- 开发库已应用 V8；实查 `projects`、`project_stack` 两张表的数量为 0。

## 5. 当前发现与风险

### 已处理：文章正文存储型 XSS 风险

文章仍由 `App.vue` 通过 `v-html` 展示，但后端现在使用 Jsoup 白名单在写入和读取边界各清洗一次。脚本、事件属性、危险 URL 协议和内联样式会被移除；已有数据库内容在读取时也会重新清洗。安全回归测试已验证恶意文章不会把危险 HTML 返回给公开接口，安全文本结构仍然保留。

长期仍建议将文章正文迁移为 Markdown 或结构化编辑器 JSON，在统一渲染管线中生成 HTML，减少任意 HTML 输入面。

### 已处理：V8 静默丢弃项目数据——FlywayMigrationStrategy 归档预防护

`V8__remove_projects.sql` 对生产库执行 `DROP TABLE projects / project_stack` 会静默丢弃 V1-V4 期间累积的项目数据。V8 已发布（checksum 不可再变），V1 包含种子数据且生产可能还有自主录入的项目行。

**修复方案（非入侵式）：** 注册 `FlywayMigrationStrategy` Bean（`FlywayMigrationConfig`），在 `flyway.migrate()` 之前调用 `ProjectArchiveService.archive()`：
- `archive()` 使用 `information_schema.tables` 检查 `projects` 表是否存在（限定 `current_schema`；元数据查询失败直接抛异常，阻止启动和迁移）。
- 若存在：创建 `projects_archived` / `project_stack_archived` 归档表（`IF NOT EXISTS`），逐行复制数据（`ON CONFLICT DO NOTHING` 幂等）。
- 若不存在（V8+ 或全新安装）：跳过归档，Flyway 正常执行。
- 归档表在 V8 之后仍然保留，为审计和未来迁移提供安全网。

**自动化测试：** `FlywayUpgradePathTest` —— 在独立 schema 中执行 V1→V4→归档→V8→V9 全链路，验证归档表存续 3 行 projects + 9 行 project_stack。

**运维命令（部署前预检）：** 见 `docs/migration-preflight.md`。

### 已处理：本地登录 CORS 与会话兼容性

本地页面使用 `127.0.0.1:5174` 时曾因后端只允许 `localhost:5173` 返回 403；现在已放行本地四种来源，并在浏览器禁用 `sessionStorage` 时使用内存会话回退。管理员登录错误也会区分 401、服务端错误和网络错误。

### P1：静态回退会掩盖后端或数据库故障

公开文章请求失败时，前端会静默使用 `data.ts` 的内置文章。它提高了展示可用性，却让用户难以发现数据库、部署或代理已经故障，也会形成数据库内容与内置内容双重事实来源。

生产环境建议取消静默回退：显示可恢复的错误状态并上报监控；仅在开发或演示模式通过显式环境变量启用本地种子内容。

### P1：前端没有自动化测试框架

`package.json` 目前只有开发和构建脚本，没有 Vitest、Vue Test Utils 或 Playwright 测试命令。此次浏览器验证是人工端到端冒烟，不能在每次提交中自动复现。

建议加入：

1. Vitest：API 适配、分页、筛选、收藏和路由状态。
2. Vue Test Utils：后台表单、错误提示、编辑器关键状态。
3. Playwright：登录、文章/菜品/笔记 CRUD、分页、发布可见性、附件上传、移动端导航。

### P1：缺少持续集成质量门禁

建议为每次提交自动执行：后端测试、前端构建、前端测试、`npm audit`、迁移校验和 `git diff --check`。部署前再执行一次独立 PostgreSQL 端到端测试。

### P1：PostgreSQL 与 Flyway 的支持范围提示

当前测试数据库是 PostgreSQL 18.4。测试日志提示随 Spring Boot 依赖带入的 Flyway 明示支持到 PostgreSQL 17，虽然本次 V1–V8 全部成功，但正式升级或上线前应升级到明确支持 PostgreSQL 18 的 Flyway 版本，或把生产 PostgreSQL 固定在团队已验证的版本。

### P2：前端主文件体积过大

`App.vue` 约 501 行，`styles.css` 约 1626 行，并承担多个公开路由和大量动效。继续添加功能会提高回归和样式冲突概率。

建议按路由拆分 Home、Articles、ArticleDetail、About；把导航、页脚、搜索、返回顶部和樱花背景拆成独立组件；把滚动、主题、收藏、内容加载拆为 composable；CSS 按 token、layout、component、page、motion 分层。

### P2：管理员会话仍依赖浏览器可读 Token

`sessionStorage` 比长期 `localStorage` 风险更低，但依然能被同源脚本读取。完成 HTML 清洗后，可进一步评估 HttpOnly、Secure、SameSite Cookie 与 CSRF 防护组合；同时对登录增加速率限制、失败审计和可选双因素认证。

### P2：生产可观测性不足

目前有 Spring Actuator 健康检查，但尚未看到结构化日志、错误追踪、指标告警和前端异常上报。建议增加请求 ID、认证失败审计、慢查询监控、5xx 告警和前端错误采集。

### P3：生产包存在大块警告

KaTeX chunk 约 744 KB（gzip 约 228 KB），Vite 报出超过 500 KB 的警告。它已被独立 chunk，不影响构建成功，但可在进入学习笔记页面时再动态加载 KaTeX，并评估只加载所需字体格式。

## 6. 推荐实施路线

### 第一阶段：安全与可信数据（优先）

1. 将静态文章回退限制为开发模式，生产接口失败显示明确错误。
2. 为删除项目表的生产迁移建立备份与回滚说明；部署前导出旧项目数据归档。
3. 解决 PostgreSQL 18 / Flyway 兼容性提示。

### 第二阶段：可持续测试

1. 建立 Vitest + Vue Test Utils。
2. 建立 Playwright 真实 PostgreSQL 测试场景。
3. CI 中使用临时 PostgreSQL 容器执行 V1–V8、CRUD 与分页测试。
4. 为重要路径设置覆盖率门槛，但优先关注关键业务分支而非单纯百分比。

### 第三阶段：前端结构治理

1. 拆分路由页面和公共组件。
2. 拆分 CSS 并建立设计 token。
3. 将内容请求、分页、错误状态统一为 composable。
4. 为骨架屏、空状态、错误重试和离线状态建立一致交互。

### 第四阶段：内容与运营能力

1. 为文章增加 SEO 元数据、Open Graph、站点地图和 RSS。
2. 为文章、菜品、笔记增加后台搜索、排序和批量操作。
3. 为图片增加数据库元数据与对象存储方案，避免数据库长期承载大量媒体二进制。
4. 增加发布预览、定时发布、草稿历史和软删除恢复站。

### 第五阶段：上线运维

1. 建立数据库自动备份、恢复演练和迁移前快照。
2. 配置 HTTPS、反向代理安全头、CSP、HSTS 和上传内容限制。
3. 增加结构化日志、指标、错误追踪和告警。
4. 使用无停机部署与迁移检查清单，发布后执行健康和核心业务冒烟。

## 7. 验收结论

本次要求的项目模块后端接口及其完整链路已经删除，数据库表已通过正式迁移移除，前端与后台也不再保留不可用入口。文章、菜品、学习笔记、附件、认证、分页、HTML 安全清洗和构建均已在真实 PostgreSQL 环境验证通过。

项目当前适合继续功能迭代；在公开上线或扩大管理员使用范围前，应优先完成 HTML 清洗、生产数据源单一化和自动化端到端测试三项工作。
